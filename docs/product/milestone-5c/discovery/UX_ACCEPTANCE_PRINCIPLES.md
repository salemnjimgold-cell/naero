# UX Acceptance Principles

These are implementation gates, not aspirations.

1. **First value:** a guest reaches a useful sourced result within five interactions after language selection.
2. **Permission restraint:** no OS permission appears before a plain-language benefit screen; every request has “not now,” and location has manual-city parity.
3. **Truthful personalization:** every personalized Home value is traceable to current state, user input or a named source; zero hard-coded user facts appear as live data.
4. **Recovery:** every loading failure and meaningful empty state explains the state and provides retry, change filters/city, offline/saved fallback, or contact action as applicable.
5. **Authority:** 100% of consequential content displays source type; official/verified/community/external/AI types are distinguishable without color.
6. **Freshness:** administrative, healthcare and safety guidance displays jurisdiction plus reviewed/effective date; stale content cannot appear as current without warning.
7. **AI uncertainty:** consequential AI answers expose sources, assumptions and unknowns and include an official verification route; unsupported claims are not stated as facts.
8. **Guest utility:** Discover, public guides, manual city and basic AI explanation remain usable without account creation; account-only actions explain why.
9. **Location-off utility:** manual city, saved items, non-nearby search and reviewed guides remain usable after location denial or disablement.
10. **RTL:** all primary journeys pass Arabic visual/order testing at 1× and 2× text size; no clipped actions or incorrect directional icons.
11. **Localization:** locale key parity is automated; no user-facing production copy is hard-coded; layouts tolerate at least 40% string expansion.
12. **Accessibility:** 4.5:1 normal-text contrast, 3:1 large text/essential graphics, 44×44 pt targets, labeled controls, logical screen-reader order and non-color status cues.
13. **Text scaling:** core flows remain operable at 200% font scaling without hidden content or horizontal scrolling.
14. **Motion:** all nonessential/looping motion stops under reduced-motion; no action or status is motion-only.
15. **Stress usability:** Help now/Safety is reachable within two interactions from Home, Discover and search; emergency actions require no AI response.
16. **Choice clarity:** each screen has one visually dominant action; destructive and external actions are labeled explicitly.
17. **Community safety:** no community prominence before report/block/moderation, provenance and city/language boundaries pass abuse scenarios.
18. **Performance feedback:** input feedback appears within 100 ms; network operations show state within 500 ms; cancellation/retry does not duplicate actions.
19. **Privacy control:** current location mode and AI memory/history behavior can be inspected and changed in two levels or fewer.
20. **No dead modules:** navigation destinations must have real content or an honest, actionable empty state—never mock content presented as live.
