# Milestone 5C Part 1 Report

## Executive conclusion

Naero has a credible technical foundation but an honesty and product-structure gap. Its strongest real capabilities are guest/auth entry, foreground/manual location, nearby/verified discovery, AI orchestration, saving and notifications. Its current Home communicates a compelling personalized journey using fabricated data, while Community, Jobs, Safety and Services remain partly mock-backed. The recommended future is **Contextual Compass**: a hybrid of Deep Sea’s calm structural trust and Guided Compass’s professional warmth, centered on the repeatable behavior **Orient → Explain → Act → Remember**.

## Recommendation

- Direction: Contextual Compass.
- Deep Sea: **EVOLVE**, preserving depth, contrast, structure and current investment.
- Guided Compass: **EVOLVE**, preserving semantic warmth/guidance while rejecting rigid palette dogma and unsupported journey content.
- Primary navigation: **Home / Discover / Plan / My Naero**, with contextual Ask Naero. Ship Saved in place of Plan until tasks are real.
- Home: context, urgent utility, one real next step/setup state, Ask Naero, one useful-now module, resume.
- AI: cross-product interpreter with sourced uncertainty, not a generic tab chatbot.

## Direction summary

- **A — Contextual Compass:** personalized orientation and action; best mission/brand balance; high staged complexity.
- **B — Civic Atlas:** authoritative city utility; strongest immediate feasibility; risks directory/government-portal convergence.
- **C — Local Weave:** bounded community belonging; emotionally distinctive; currently blocked by moderation, trust and supply infrastructure.

Decision totals: A 126/140, B 118/140, C 105/140.

## Implementation implications

Reuse auth/SecureStore, guest mode, location/manual city, nearby gateway/provider normalization, verified-service model, AI gateway/RAG/tools, notifications, saving, caching/sync and selected theme primitives. Eventually redesign Home data contracts, navigation semantics, source indicators, personal area, localization architecture, RTL/accessibility behavior, and the task model. Community, jobs, housing and administrative promises require production data and governance before visual prominence.

## Owner decisions required

1. Approve or reject **Contextual Compass** as the direction.
2. Approve the four-destination target IA and the temporary **Saved → Plan** staging rule.
3. Decide whether Naero’s first launch market/jurisdiction should constrain content and acceptance testing before global expansion.
4. Approve the trust taxonomy and the rule that unsupported personalization is removed rather than visually preserved.
5. Choose the first real life-task domain for a future Plan pilot (for example settlement basics, healthcare access, or residency guidance); this determines content governance and risk.

## Gate

**Should implementation of this direction begin now? NO.**

Part 1 is complete, but implementation should begin only after owner approval of the direction, IA, initial jurisdiction/domain, and truth/provenance rules, followed by a scoped Part 2 implementation plan. No source, navigation, theme, backend, API or configuration changes were made in this discovery phase.
