# Future User Journey

## First ten minutes

| Stage | Experience | Emotional transition |
|---|---|---|
| Install/launch | Fast brand moment; no permissions | Unknown → curious |
| Welcome | One promise and “Explore as guest” primary; sign-in secondary | Cautious → in control |
| Language | Four visible languages, script previews, change anytime | Excluded → recognized |
| Auth/guest | Explain that account enables sync; never block first value | Suspicious → respected |
| Location | Show the nearby benefit, precise privacy statement, “Use location / Choose city / Not now” | Guarded → informed |
| City understanding | Confirm detected/selected city and allow correction | Uncertain → oriented |
| Intent | Pick one optional intent: help now, understand, find, do, settle, belong, explore | Overloaded → focused |
| Personalization | Ask no more than one follow-up needed for that intent; skip available | Questioned → understood |
| Home/result | Land on a truthful contextual Home or directly on the requested result | Waiting → progressing |
| First success | Find a sourced service/guide, obtain an explanation, save it, call/open directions, or create one legitimate step | Unsure → capable |

Target: a useful result within **five user interactions after language selection**, excluding OS dialogs and optional authentication.

## Return journey

`Install → Welcome → Language → Auth/Guest → Location/City → Intent → Home → Discover/AI/Community → Save/Act → Return`

- **Install to Welcome:** credibility before data collection.
- **Welcome to Language:** Naero adapts to the user, not vice versa.
- **Language to Guest/Auth:** value is available; continuity is a choice.
- **Auth to Location:** each permission is separate and explained.
- **Location to Intent:** broad capability becomes a specific human goal.
- **Intent to Home:** context becomes a calm priority, not a dashboard.
- **Home to Discover:** structured evidence supports browsing/comparison.
- **Home/Discover to AI:** ambiguity becomes explanation or a plan.
- **AI to Community:** only when lived experience is useful, with authority boundaries intact.
- **Save/Action:** the user owns the decision; Naero records only what was requested.
- **Return:** resume a real saved action, see a relevant verified change, or use everyday discovery—never an engagement feed.

## Minimum information before value

Required: language and a city context only when the chosen result is location-dependent. Authentication, nationality, migration status, precise location, arrival date, profession and household data are optional and requested only when a named benefit requires them.
